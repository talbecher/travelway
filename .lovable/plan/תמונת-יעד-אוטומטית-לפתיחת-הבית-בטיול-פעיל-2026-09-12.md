# תמונת יעד אוטומטית לפתיחת הבית בטיול פעיל

## מה ישתנה

פתיחת הבית בזמן טיול פעיל תקבל תמונה צבעונית גם כשאין תמונה תקינה בתחנות היום: המערכת תחפש אוטומטית תמונה של עיר היום או של יעד הטיול דרך חיבור Google Places הקיים, ותציג תמונת אווירה מקומית כגיבוי אחרון.

סדר הבחירה:

1. תמונות תחנות היום (ההתנהגות הקיימת, ללא שינוי).
2. אין תמונה תקינה → חיפוש "עיר היום + יעד הטיול".
3. אין עיר או אין תוצאה מתאימה → חיפוש היעד בלבד.
4. נכשל → תמונת אווירת טיול מקומית; כשל בטעינתה → הגרדיאנט הקיים.

היעד נלקח רק מהשדות `destination_country` ו־`city_label`, לא משם הטיול. יעד עמום או מרובה מדינות לא יפוענח בניחוש — פשוט נופלים לגיבוי.

## פרטים טכניים

### 1. `src/lib/places.functions.ts`

פונקציית שרת חדשה `getDestinationPhoto` (קריאה בלבד), לצד הקיימות וללא שינוי בהן:

- `.middleware([requireSupabaseAuth])` — זמינה רק למשתמש מחובר; נקראת מהקומפוננטה, לא מ־loader.
- קלט: `{ city?: string | null; destination: string }`.
- עד **שני** חיפושי `places:searchText` לכל קריאה (עיר+יעד, ואז יעד בלבד) ועד **שני** ניסיונות `photos/media`.
- `X-Goog-FieldMask` מצומצם: `places.id,places.displayName,places.formattedAddress,places.types,places.addressComponents,places.photos` — ללא דירוגים/ביקורות.
- אימות התאמה: המקום חייב להיות מסוג גאוגרפי (`locality`, `administrative_area_level_*`, `country`, `political`, `tourist_attraction`/`landmark` כשהשאילתה היא עיר) **וגם** רכיבי הכתובת חייבים להכיל את העיר/המדינה המבוקשת. עסק בעל שם דומה נפסל.
- תמונה: מעדיפה יחס אופקי (`widthPx > heightPx`) ורוחב מספיק; בקשה עם `maxWidthPx=1200&skipHttpRedirect=true`.
- מחזירה `{ url, attributions: string[], sourceLabel } | { url: null }`. המפתח נשאר בצד השרת.
- כשל/היעדר תוצאה → `url: null`, בלי חריגה.

### 2. `ActiveTripHero.tsx`

- פרופ חדש `destinationPhoto?: { url: string; attributions: string[] } | null` ו־`fallbackImageUrl`.
- הסדר: מועמדי היום (לוגיקת `onload/onerror` הקיימת) → תמונת יעד → תמונת אווירה מקומית → גרדיאנט.
- קולבק `onDayImagesExhausted()` שמדווח למעלה שכל מועמדי היום נכשלו, כדי להפעיל את החיפוש רק אז.
- ייחוס Google/הצלם מוצג בקריאות בפינת הפתיחה (טקסט קטן מעל ההצללה), רק כשמוצגת תמונת Places.
- נשמרים: מבנה פנורמי קומפקטי, ללא הלבנה, הצללה כהה עדינה, מזג האוויר והטקסטים.

### 3. החיבור ב־`src/routes/index.tsx` (ענף פעיל בלבד)

- state מקומי `dayImagesExhausted`; `useQuery` עם `enabled: tripIsActive && dayImagesExhausted && isOnline && !!destination`, `staleTime` ארוך, ללא retry אוטומטי.
- `queryKey` כולל trip id, day id, עיר ויעד — החלפת יום/טיול מאפסת אוטומטית את הבחירה ומתעלמת מתשובות ישנות; `dayImagesExhausted` מתאפס עם שינוי היום.
- אין שמירה ב־DB או ב־localStorage; התמונה לאווירה בלבד ולא מוצגת כתחנה בתכנון.
- הטעינה אינה חוסמת: שאר הבית מוצג מיד.

### 4. תמונת גיבוי מקומית

נוצרת תמונת אווירת טיול כללית (נוף/מזוודה־הרפתקה, ללא טקסט) ונשמרת ב־`src/assets`, מיובאת כ־import רגיל.

## מה לא משתנה

תמונות התחנות, מזג האוויר, לוגיקת הזמן, הפעולות, הניווט, הבית שלפני ואחרי הטיול, ה־DB, התלויות וספק המפות.

## בדיקות

בנייה ובדיקת טיפוסים בלבד. אם `GOOGLE_PLACES_KEY` או השירות אינם זמינים — הגיבוי עובד, ואדווח על כך בקצרה.  
  
התוכנית בכיוון הנכון. **לפני המימוש צריך לתקן ארבע נקודות קטנות:**

- **אימות היעד:** לא להסתמך על התאמת טקסט מדויקת בלבד — `Italy` ו־״איטליה״ יכולים לייצג אותו מקום. להשתמש ברכיבי הכתובת ובקוד המדינה כשזמין. `political` לבדו אינו הוכחה להתאמה.
- **ייחוס התמונות:** `attributions: string[]` אינו מספיק. לשמור את פרטי הייחוס המובנים שמתקבלים מ־Google, כולל שם וקישור, ולהציגם כנדרש.
- **מטמון:** להסיר את ההנחיה ל־`staleTime` ארוך באופן גורף. הפניות התמונות אינן קבועות; צריך טיפול בכשל ובהתיישנות בהתאם לתנאי השירות.
- **React ואיפוס:** לא לקרוא ל־`useQuery` בתוך ענף מותנה. להשתמש ברכיב ייעודי לבית הפעיל או ב־Hook שמופעל ללא תנאי עם `enabled`. לאפס את `dayImagesExhausted` גם בהחלפת טיול ובשינוי מועמדי התמונות, ולא רק בהחלפת יום.

יתר התוכנית ממוקד ומתאים. אפשר להמשיך למימוש עם התיקונים האלה, **בלי להוסיף בדיקות או להרחיב את הסבב.**
