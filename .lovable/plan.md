# תוכנית יישום — רענון UI למסך ההמלצות לפי A2

## ממצאי הבדיקה

מסך ההמלצות ממומש ברובו בקובץ אחד: `src/routes/recommendations.tsx`. בתוך הקובץ נמצאים מבנה המסך, המסננים, רשימת ההמלצות, כרטיסי המקום, כרטיסי המלונות, מצב הבחירה המרובה, פעולות ההוספה והייבוא, והחיבור למפה ול־Discover.

הרפרנס המצורף הוא export סטטי ברוחב 390px וכולל Tailwind CDN, Google Font, SVG paths, תוכן דמה ופעולות דמה. הוא ישמש רק למבנה, צפיפות, מידות והיררכיה; אף אחד מהחלקים האלה לא יועתק כקוד.

| מעטפת וניווט | `src/routes/__root.tsx`, `BottomNav` | רוחב התוכן, safe-area, GlobalFab והניווט הקבוע |

### ממצא חשוב: “כבר נוסף ליום”

בכרטיס ההמלצה ברשימה אין כיום טעינה או state שמזהים לאילו ימים ההמלצה כבר נוספה. זיהוי כזה קיים בהקשר של Discover, לא בכרטיסי `PlaceCard`. לכן הרענון לא ימציא תג חדש ולא יוסיף query. פעולת ההוספה ליום וההתנהגות הקיימת נשמרות בדיוק; אם בעתיד יועבר לכרטיס state קיים כזה, יהיה ניתן להציגו ללא שינוי מבני נוסף.

## קבצים שיידרשו לשינוי

1. **`src/routes/recommendations.tsx`**
   - בניית היררכיית A2 לכותרת, Discover ומתג רשימה/מפה.
   - איחוד החיפוש, סוג המקום, העיר ו“נוספו הרגע” לאזור סינון קומפקטי.

## תוכנית היישום

### 1. מעטפת וכותרת
- לתת למסך רקע וטיפוגרפיה תואמי A2 דרך `bg-background`, `bg-card`, `border-border`, `text-foreground`, `text-muted-foreground`, `accent` ו־`surface-2` הקיימים.
- לשמור את מעטפת ה־AppShell, סרגל האפליקציה והפעולות הגלובליות כפי שהם; לא להעתיק את הסרגל העליון מהדמו.
- להציג כותרת ותיאור במבנה אנכי, ולמקם את פעולת הבחירה הקיימת ללא שינוי handler.
- במצב בחירה מרובה, לשמור את כפתור הביטול והסרגל הקיים; רק לעצבם כך שלא יתנגשו עם BottomNav וה־safe-area.

### 2. Discover ומתג תצוגה
- למקם בשורה אחת גמישה את Discover ואת מתג הרשימה/מפה.
- Discover לא ירונדר אם הדגל כבוי או המשתמש אינו מורשה; `useDiscoverAccess`, `discoverEnabled` ו־`DiscoverSheet` לא ישתנו.
- בטאב מלונות, המפה תישאר מוסתרת כפי שהיא היום וה־selection mode ימשיך להיסגר לפי ה־effects הקיימים.

### 3. אזור סינון מאוחד
- שדה החיפוש בראש האזור.
- segmented control לסוג המקום מתחתיו.
- שורת מסננים משנית עם בורר עיר ו“נוספו הרגע” כאשר רלוונטי.
- בורר העיר יקבל options מ־`cities` הקיים בלבד, ישמור `city === "all"`, ויקרא רק ל־`setCity`; אין query, fetch או state נוסף.
- כאשר פילטרים פעילים, מצבם יהיה ברור באמצעות active styling והערכים הנבחרים. פעולת איפוס מקומית תאפס רק `q`, `city` ו־`recentOnly`; שינוי הטאב ימשיך לאפס עיר באמצעות ה־effect הקיים.
- הבורר והכפתורים יהיו ברוחב גמיש, ללא גלילה אופקית ב־360px.

### 4. כרטיסי ההמלצות
- להסיר את בלוק ה־hero כולו מתוך `PlaceCard`, כולל gradient/emoji fallback שמשרתים רק אותו.
- לא להסיר `photo_url` מ־`Rec`, מ־`mapPins`, מ־`RecForm`, מ־`PhotoUploader`, מ־`AdminBackfillButton` או מ־`RecsMap`.
- לנקות רק constants/imports שהופכים ללא שימוש ורק אם TypeScript דורש זאת.
- לבנות card קומפקטי עם border חם, radius 16px וללא shadow כבד:
  1. שורת סוג/status וכלים.
  2. שם המקום כשכבת המידע הראשית.
  3. עיר וכתובת אם קיימות; כל אחת תוכל להישבר בלי overflow.
  4. deadline, דירוג Google, מרחק, notes, rating/review — רק כאשר הנתונים קיימים, ובצפיפות מבוקרת.
  5. “נוסף עכשיו” מתוך `recentIds` הקיים.
  6. CTA ראשי להוספה ליום וניווט משני רק אם קיים URL.
  7. פעולות status הקיימות בלבד.
- במצב בחירה מרובה, הכרטיס כולו נשאר אזור בחירה; checkbox ברור, ללא פעולות עריכה/מחיקה/ניווט/הוספה כפי שהקוד כבר עושה.
- לשמור `stopPropagation` בכל פעולה פנימית, confirm מחיקה, mutations, pending/error ו־aria-labels.

### 5. מלונות
- לשמר את טאב המלונות ואת כל הלוגיקה הנפרדת שלו.
- לעצב `HotelCard` באותה שפה קומפקטית: מידע מרכזי ראשון, סטטוס ביטול, תאריכים/לילות/עלות, CTA הוספה למסלול ופעולות עריכה/מחיקה.
- לא להפוך מלון לכרטיס המלצה רגיל ולא לשנות `HotelForm`, סנכרון מסלול, cascade delete או PostStayForm.

### 6. פעולות הוספה וייבוא
- להסיר את המיקום הקבוע של כפתורי הייבוא וההוספה בלבד, לא את ה־handlers או הגיליונות.
- בסוף תצוגת הרשימה והמלונות, להציג:
  - “ייבוא ממפה” ו“ייבוא מ־AI” בשורה של שני טורים.
  - “הוספת מקום” בשורה מלאה מתחת.
- כל כפתור יהיה לפחות 48px, עם Lucide קיים, text wrapping תקין ו־focus ring.
- האזור לא יוצג מעל המפה כדי לא לכסות אותה; במצב מפה נשמרת ההתנהגות המלאה של המפה, והפעולות יחזרו עם המעבר לרשימה.
- האזור לא יהיה sticky; מעטפת המסך הקיימת כבר מספקת padding תחתון המחושב עם safe-area ו־BottomNav.

| חיפוש וסינון | אותם ערכים ואותן פונקציות; רק controls חדשים סביבם |
| מפה | RecsMap, Leaflet, markers, bounds, clustering ומיקום המשתמש ללא שינוי |
| תמונות | השדות, הטפסים, backfill והמפה נשמרים; רק hero ברשימה אינו מרונדר |
| ייבוא ממפה / AI | אותם רכיבים, props, handlers ושמירה |
| הוספה/עריכה ידנית | RecForm, PlacesSearch, PhotoUploader ו־BottomSheet ללא שינוי |
| מלונות | queries, HotelForm, sync, delete, deadlines ו־post-stay ללא שינוי |
| offline | `assertOnline` וההתנהגות הקיימת ללא שינוי |
| BottomNav / GlobalFab | ללא שינוי |

## סיכונים וצמצום

1. **קישור בתוך קישור בכרטיס הנוכחי** — כיום הכרטיס כולו הוא `<a>` כאשר יש Maps URL, ובתוכו קישור ניווט נוסף; יומן הדפדפן כבר מציג אזהרת hydration על nested anchors. הפתרון יהיה להפוך רק את עטיפת הכרטיס ל־`div` ולשמור ניווט מפורש בכפתור המשני. אין שינוי URL או פעולה עסקית.
2. **אובדן שימוש בתמונות** — הסרת ה־hero עלולה לגרור בטעות ניקוי רחב. יוסר רק JSX הכרטיס וה־fallback המקומי; `photo_url` וכל שרשרת התמונה יישארו.
3. **פער בין פילטרים במסך לבין הרשימה** — `Recs` ו־`PlacesList` מסננים בנפרד. לא נאחד או נשכתב לוגיקה; controls ימשיכו להזין את אותם props/state כדי למנוע שינוי תוצאות.
4. **בחירה מרובה מול פעולות כרטיס** — נשמר הפיצול הקיים בין wrapper לבחירה לבין פעולות רגילות, כולל עצירת propagation.
5. **היעדר state “כבר ביום”** — לא יוצג מידע שאין לו מקור אמת קיים; לא תתווסף שאילתה חדשה.
6. **הרבה ערים ושמות ארוכים** — select טבעי, `min-w-0`, `break-words`, שתי שורות לשם ושבירה מבוקרת לכתובת.
7. **פעולות סוף הרשימה במצבי empty/no-results** — אזור ההוספה יהיה sibling של התוכן ולא חלק מ־`PlacesList`, כך שיישאר נגיש גם כשהרשימה ריקה; במצב map לא יכסה את המפה.
8. **סרגל בחירה מול BottomNav** — יישמר fixed רק לסרגל הבחירה הקיים, עם offset הכולל safe-area; פעולות ההוספה עצמן לא יהיו fixed.
9. **dark mode** — לא ייעשה שימוש בצבעי light קשיחים; coral בהיר ייבנה מ־`accent` עם `color-mix`/opacity וטוקנים קיימים.
