# ייבוא משימות מ־AI לצ׳ק־ליסט

## מה קיים
- טבלת `checklist_items`: `title` (חובה), `category` (טקסט, ברירת מחדל `other`), `priority` (טקסט, ברירת מחדל `normal`), `notes`, `due_date` (date), `is_done` (ברירת מחדל false), `display_order`. גישה לפי `can_access_trip`. אין אילוצי CHECK במסד — האימות חייב להיות בצד הלקוח.
- קטגוריות קבועות בקוד: `documents, money, bookings, health, tech, packing, departure, other`. עדיפויות: `high, normal, low`.
- `useBulkAddItems` כבר מכניס מערך משימות בקריאה אחת לטיול הפעיל ומרענן את הרשימה; משמש היום לתבניות.
- `ImportAISheet` קשור למסלול/המלצות (ימים, Google, החלפה) — לא יורחב. ישמש רק `BottomSheet` הקיים.

## מה ישתנה
- כפתור „ייבוא מ־AI” בראש מסך הצ׳ק־ליסט, פותח חלונית חדשה: הדבקה → תצוגה מקדימה → בחירה → „הוסף X משימות”.
- דוגמת JSON להעתקה בתוך החלונית.
- הוספה בלבד; משימות חדשות נשמרות כלא־הושלמו (`is_done` לא נשלח).

## פורמט JSON
```json
{
  "version": 1,
  "checklist": [
    { "title": "להזמין eSIM", "category": "tech", "priority": "high", "due_date": "2026-11-20", "notes": "לבדוק תמיכה בטלפון" },
    { "title": "מתאם חשמל", "category": "packing" }
  ]
}
```
- `title` חובה (עד 200 תווים). `category` אופציונלי, אחד מ־8 המזהים; חסר → `other`. `priority` אופציונלי: `high|normal|low`; חסר → `normal`. `due_date` אופציונלי, `YYYY-MM-DD` ותאריך אמיתי בלוח השנה. `notes` אופציונלי.
- ערך לא מוכר (קטגוריה/עדיפות/תאריך) או כותרת חסרה → הפריט מוצג כלא תקין עם הסבר, לא ניתן לבחירה ולא נשמר. אין המרה שקטה.
- אותו חילוץ JSON מגודר/גולמי כמו בייבוא הקיים (שימוש חוזר ב־`extractJsonBlock`).

## זיהוי כפילויות
- נרמול כותרת: trim, איחוד רווחים, lowercase (שימוש חוזר ב־`normalizeEntryName`).
- קיימת בטיול (כולל שהושלמה) → „כבר קיימת”, לא מסומנת.
- כפילות בתוך הקלט → רק המופע הראשון מסומן (אלא אם הוא כבר קיים), השאר „מופיעה פעמיים בייבוא”.
- כל כפילות תקינה ניתנת לסימון ידני.

## שמירה ושגיאות
- `useBulkAddItems` עם הנבחרות בלבד, `trip_id` של הטיול הפעיל, `display_order` המשך לרשימה הקיימת.
- הכפתור נעול בזמן שמירה ובספירה אפס; `assertOnline` לפני שמירה.
- הצלחה: toast, רענון, סגירה. כשל: הודעת שגיאה, הקלט והבחירה נשמרים, אין ניסיון חוזר אוטומטי.
- איפוס בסגירה ובמעבר טיול; תוצאה ששייכת לטיול קודם (בדיקת tripId בזמן הסיום) מתעלמת.

## סיכונים
- אין אילוצים במסד, כך שהגנת הערכים היא בקוד בלבד (בהתאם לבקשה, אין שינוי סכמה).
- כפילות מקבילה (מכשיר אחר מוסיף באותו רגע) לא תיחסם — הגנת ממשק בלבד.
- אין כרגע בדיקות בפרויקט; יתווסף vitest כ־devDependency אם אינו זמין דרך bunx (כלי בדיקה בלבד, לא ספריית אפליקציה).

## אימות
- בדיקות: JSON תקין, ברירות מחדל, כותרת חסרה, קטגוריה/עדיפות לא מוכרות, תאריך לא תקין (`2026-02-30`), כפילות קיימת כולל שהושלמה, כפילות בתוך הקלט, הבדלי רווחים/אותיות.
- `bunx tsgo --noEmit` ו־`bun run build`. ללא דפדפן, צילומים או נתונים אמיתיים.
