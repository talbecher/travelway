# שיפור הצ׳ק־ליסט: בקשה ל־AI, קטגוריות ומיון לפי דחיפות

## מה קיים (אומת בקוד)
- אין אילוץ במסד על `category`/`priority` — האכיפה בקוד בלבד. אין צורך בשינוי סכמה.
- משימה עם קטגוריה לא מוכרת **לא מוצגת כלל** היום: הקבוצות נבנות רק מ־`CHECKLIST_CATEGORIES`.
- טופס העריכה שולח תמיד `category` — ולכן גם שמירה של שדה אחר כותבת את הקטגוריה מחדש.
- `PRIORITY_LABEL` משוכפל ב־`checklist.tsx` וב־`ImportChecklistSheet.tsx`.
- המיון בתוך קטגוריה: לפי השאילתה (`display_order`, `created_at`) בלבד.
- במצב ריק מוצג מסך פתיחה בלי כפתור ייבוא.
- `todayLocal()` קיים ב־`src/lib/format.ts`.

## מה ישתנה
1. **בקשה מוכנה ל־AI** — כפתור „העתק בקשה ל־AI” בחלונית הייבוא, לצד הדוגמה הקיימת. הבקשה נבנית מאותן הגדרות משותפות, כוללת יעד ותאריכי טיול מהנתונים שכבר נטענים (`useTrip`), ללא שאילתות חדשות.
2. **transport — „תחבורה” 🚆** נוסף להגדרה המשותפת, ומשם לטופס, לעריכה, לסינון, לתצוגה ולייבוא. ללא תבנית חדשה.
3. **ייבוא סלחני** — מזהה קטגוריה עובר trim + lowercase; `booking`→`bookings`, `finance`→`money`, עם הערה עדינה „הקטגוריה הותאמה ל־הזמנות/כספים”. ערך לא מוכר אחר נשאר שגיאה. גם עדיפות עוברת trim + lowercase בלבד.
4. **fallback לקטגוריה לא מוכרת** — משימות כאלה מוצגות בקבוצת „אחר”, ניתנות לסימון ולעריכה. בעריכה, `category` נשלח רק אם המשתמש שינה אותו בפועל; הערך במסד לא נכתב מחדש.
5. **מקור אחד לעדיפויות** — `CHECKLIST_PRIORITIES` ו־`PRIORITY_LABEL` עוברים ל־`checklist-templates.ts`.
6. **מיון תצוגה** בתוך כל קטגוריה (פונקציה טהורה, ללא כתיבה ל־`display_order`):
   1. פתוחות באיחור, 2. פתוחות להיום, 3. שאר הפתוחות, 4. שהושלמו בסוף.
   בתוך קבוצה פתוחה: high → normal → low, אחר כך תאריך יעד קרוב קודם, ללא תאריך בסוף; שוויון: `display_order`, `created_at`, `id`. „היום” לפי `todayLocal()` כמחרוזת YYYY-MM-DD, ללא המרת UTC.
7. **תוויות** — „באיחור”, „להיום”, „עדיפות גבוהה” כטקסט (מחליף את ה־🔴 בלבד); למשימה שהושלמה אין תווית איחור. כותרת קבוצה: אייקון, שם ומספר פתוחות. מצב פתיחת הקבוצה נשמר לפי מזהה קטגוריה ולכן לא מתאפס בסימון; מפתחות השורות לפי `id` כדי לשמור מיקוד מקלדת.
8. **ייבוא במצב ריק** — כפתור „ייבוא מ־AI” גם במסך הפתיחה, לצד הפעולות הקיימות.

## דוגמת הבקשה לצ׳אט
```text
החזר JSON בלבד, בלי טקסט נוסף, עבור צ׳ק־ליסט הכנה לטיול ל<יעד> (<התחלה>–<סיום>).
מבנה: { "version": 1, "checklist": [ { "title", "category", "priority", "due_date", "notes" } ] }
- title חובה, עד 200 תווים. השאר אופציונליים.
- category אחד מ: documents, money, bookings, transport, health, tech, packing, departure, other (ברירת מחדל other).
- priority אחד מ: high, normal, low (ברירת מחדל normal).
- due_date רק כשיש מועד אמיתי וידוע, בפורמט YYYY-MM-DD. אל תמציא תאריכים.
- אל תכלול משימות שהושלמו או משימות שכבר קיימות בצ׳ק־ליסט אם הן ידועות לך.
דוגמה: <הדוגמה הקיימת>
```

## קבצים
- `src/lib/checklist-templates.ts` — transport, עדיפויות ותוויות משותפות.
- `src/lib/checklist-import.ts` — נרמול ומיפוי, הודעת התאמה, בונה בקשה.
- `src/lib/checklist-sort.ts` (חדש) — מיון ותיוג דחיפות, טהור.
- `src/components/ImportChecklistSheet.tsx` — כפתור העתקת בקשה, הצגת הודעת התאמה.
- `src/routes/checklist.tsx` — fallback ל„אחר”, מיון, תוויות, ספירת פתוחות, עריכה ששולחת קטגוריה רק בשינוי, ייבוא במסך ריק.
- בדיקות: `src/lib/checklist-import.test.ts` + `src/lib/checklist-sort.test.ts` עם `bun test`.

## סיכונים ממשיים
- ChatGPT עלול להחזיר `transport` בכל זאת לפני שהמשתמש מעתיק בקשה חדשה — עכשיו זו קטגוריה תקינה, אז אין בעיה.
- ה־API החיצוני מחזיר `category` כמחרוזת; `transport` יופיע שם כערך חדש — אין שינוי בקוד ה־API.
- המיון שונה מהסדר הנוכחי; משימה שסומנה תזוז לסוף הקבוצה (מכוון).
